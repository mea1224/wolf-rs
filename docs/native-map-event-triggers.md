# Map event activation and player movement

Target: GamePro.exe SHA-256 `13e7cf22b8b2e700f492794b4dd1b6f28ebe76d59165c1c188b95ac31b0c3b9d`.

The scheduler previously launched only automatic (1) and parallel (2) pages. Confirmation (0), player contact (3), and event contact (4) never reached a VM instance. This prevented interactions and script-driven map transfers after player takeover, independently of opcode 130 support.

`game.rs` now keeps a pending flag per selected page and launches all nonparallel kinds through the one native main context. Selection remains reverse page-condition order; launch remains ascending event ID. Replacing a page cancels its old fiber and clears pending activation. Cross-map transfer destroys old actor-owned parallel fibers but preserves the active main context, so commands after opcode 130 still execute. Destination automatic pages wait for that main context to finish. Pending state is included in the host save payload.

Native evidence is in `validation/native-scene-movement/`:

- `player-event-query.asm`: 9F63E0 overlap and 9F6900 front interaction. `player-confirm-query.c` preserves REA pseudocode for the complete 9F6900; assembly remains authoritative for branches.
- `movement-event-trigger.asm`: 9F72D0 blocked walking checks types 3/4.
- `event-touch-query.asm`: 9F94A0 event contact and 9F9720 version-dependent maintenance.
- `event-touch-filter.asm`: 9F8A20 distinguishes visible solid events from floor overlaps. Page graphics retain the terminal NUL, so byte length alone does not establish a nonempty graphic.
- `tile-counter-query.asm`: complete 9FF930..A00017 counter query, tile flag 0x80 and configured one/six-point sampling.
- `tile-direction-passability.asm`: 9FEDE0 source/target directional tile flags. `actor-collision.asm` shows 9EFCB9..9EFD0D querying both source facing and opposite target facing.
- `actor-screen-position.asm`: 9F04E0/9F0590 convert interpolated actor quarters to screen feet, including signed rounding, jump/height offsets, loops and pixel offsets. Opcode 124 properties 4, 6, 7 and 9 use these actual actor properties; Common37 PC83 requires property 6 for normal map interaction.
- `transfer-0x96ECD0.c`, `transfer-0x94C0E0.c`, `transfer-0xA3DA30.c`, and `map-actor-destroy.asm`: the A416D0 transfer path clears resources and old actors, without resetting the independent main context.
- `context-map-initialize.asm`, `common-slot-start.asm`: A053D0 captures the current map for every new context, including independently started common slots. `transfer-0xA05800.c`, `context-map-setter.asm`, and `map-self-getter.asm` establish that version 317+ common commands use the current map, while map commands use the context's originating map. The VM retains both maps' variable banks across transfers and saves.

Transfer flag high nibble 1 starts the configured transition, and 2 also enables a black backdrop and blocks the VM until that transition completes (A18560/A18868, A40430/A41143, A06570). The map transaction does not replace these modes with a fixed effect or duration.

Opcode 211 is a main-context reservation, not an independent parallel spawn. `common-reserve.asm` (A1CEE7) stores one common ID in 14DEC24; repeated reservations replace that slot. A05DB0 checks it before map event candidates, starts it in the idle main context, then clears the slot at A05E69. The previous independent-spawn model kept system variable 13 false, so Common3 could start three Common9 menu contexts from a three-tick key press. The physical menu regression asserts exactly one Common9 instance and an active main context.

The IR now distinguishes `NativeReserve` from generic asynchronous `Reserve`. Its target uses contextual numeric resolution, including common-self operands found in Common69. Targets at least 600000 apply the native relative-common formula, clamped to the common table; lower targets set a current-map event flag. A05E76 clears pending input/touch types 0/3/4 when a reserved common takes the main context. Pending common and map state are serialized in VM save version 11. The dedicated common main slot is reused. Three VM regressions cover coalescing while main is busy, system 13, save restoration, dynamic/relative targets, and map-bound flags. The actor page-hold field at +0x360 has no separate supported host representation yet.

`tools/audit_actor_effects.py` enumerates all 1051 pages for stationary animation and effect-name candidates. There are 712 pages with the stationary flag (many have empty graphics), including Map001 event10 `hikari.png` and Map031 event3 `effects02x2.png`, both configured for additive blending. `local_stationary_effect_sprites_advance` exercises those real pages plus Map000 event48 `effects01x2.png`, recording animation phase times and rendered sprite frames. These are visual fixtures; their presence does not establish which unspecified point-flash effect the user observed, nor prove every fixture's story reachability.

`native_scene/trigger.rs` reads the selected page's actual expansion bytes and actor properties. It handles overlap, blocked contact, front confirmation, counter extension, and loop boundaries without map or event ID exceptions. Type 3 is activated on arrival; type 4 is rechecked on overlap. In 9F7780, the stationary mask `v28=0,v29=1` enables byte 4, whereas the arrival mask enables byte 3. Treating those masks as the same trigger would restart ordinary transfer pages while the player stands still.

Default player input now obeys main-context activity, input policy, actor movement readiness, configured direction count and step width. Facing updates before collision checks; interpolation and forced movement remain in RouteState. The original input adapter remains the only source of logical confirmation and directions.

The November 18 continuation also fixes the player's initial collision height. The constructor calls `9ECDE0` at `9F59DF`: `9ECDE0..9ECDED` reads FA523C (`Game.dat configuration[9]`) and sets actor+B5 when that byte equals 1; `9ECDF3..9ECDFF` independently sets the step width from FA5238 (`configuration[8]`). The prior implementation initialized the step width but left player height false. In the real Map001 takeover state, the player at (34,16) facing right could therefore never reach the half-grid action at (36,15), even though its script was present. `RouteState::configure(player=true)` now applies the native height setting; map actors retain page flag 0x20. A generic wall/odd-half-grid regression covers both configuration values. A fresh-start regression now reaches the mirror by actual Up/Right input; the subsequent Common37 picture query is tracked independently from movement. Historical checkpoints retain the previously serialized actor height and cannot validate a fresh constructor fix.

Verification is split between synthetic geometry/directional tests in `trigger.rs` and the real archive takeover interaction test. A passing interaction does not establish every autonomous movement route, collision variant, or original-save scenario. Event-facing restoration/locking and directional diagonal corner ordering still require separate native equivalence checks; the implementation must not be reported as full-engine parity on these grounds.
