# 原生窗口配置字段

本轮静态分析针对当前 GamePro.exe SHA256 `13e7cf22b8b2e700f492794b4dd1b6f28ebe76d59165c1c188b95ac31b0c3b9d`。

`459460` 是配置对象的指针绑定函数。`4596E9` 读取对象 `+10` 的 u16 向量；`459773/459776` 将向量 `+20`（word16）绑定到对象 `+180`；`45977C/45977F` 将 `+22`（word17）绑定到 `+184`。全局对象地址 `FA5180`，故两指针为 `FA5300/FA5304`。`A550F9..A55131` 解引用为有符号16位宽高，经原生低分辨率倍率处理后传给显示初始化函数 `7681E0`。当前配置的这两个字段是1280×720，不能写死该尺寸。

`4597B2/4597B5` 将word22绑定至 `FA5314`。INI函数 `9B8B30` 在 `9B9C95` 保存 `Start_Window_Scale[x0.1]=` 数值至 `FA2B00`；缺失键时 `9B9CD3` 写入-1。启动消费者 `A592B5` 检查非正值，`A59496..A594A8` 改用word22，配置零值被替换为1000。`A594BF` 的常量 `CA7D90` 为double **0.001**；所以实际实现单位是千分比，不能依据INI键名称乘0.1。随后转为float，并与宽高可用区域比例的较小值取min。`93EDE0` 将第二缩放参数-1替换为第一参数，实现等比缩放；非正的结果归一为1。

`WindowModeFlag` 缺失默认1，按两个字符执行atoi。`Display_Number` 缺失默认0，按一个字符执行atoi。模块保留原始模式值。窗口模式0走稍后的自定义无边框全屏路径；不能将此路径称为已证实的独占全屏。

`window_config.rs` 以配置word数组和INI文本为输入，分别给出逻辑宽高和初始显示倍率。平台层可用 `scale_fitting` 传入原生所用 `GetSystemMetrics(16/17)` 的结果；不能用任意固定桌面尺寸替代。当前配置（1280×720、word22=1000、INI=-1）得到1倍。小分辨率原生特殊倍增分支、完整DPI与像素舍入、全屏转换仍应由平台显示层单独处理。

证据：`validation/native/window-config-binding.asm`、`window-main-entry.asm`、`window-pointer-candidates.json`，以及 `docs-append/evidence/startup-native/9B8F58.c` 和 `93EDE0.c`。

## 显示器与窗口模式复核

- `A56D9D/A56DA3` 对正数Display_Number先减1，随后调用 `768720`；因此编号1表示原生枚举索引0。`7687AF..7687B7` 验证索引小于显示器数，越界返回-1且不修改已选索引。
- 编号0进入自动选择：`A5613C/A5613F` 以-1调用 `768720`；`A56172` 调用IAT `C012E4=GetCursorPos`，`A56186` 调用 `C01304=MonitorFromPoint`，flags为2。后续 `C01318=EnumDisplayMonitors`、`C01334=GetMonitorInfoA` 获取显示器信息。自动选项应按鼠标位置选择最近显示器，不能固定为第一个或主显示器。`monitor_index()` 将正数转为零基索引，0返回None；`native_cursor_position()` 给平台层提供选择输入。winit枚举顺序与原生图形设备枚举顺序尚未逐设备比对。
- `A584CA..A584EC` 对WindowModeFlag为0或1均调用 `93E9A0(1)`。`93E9A0` 日志字符串为 `ChangeWindowMode実行`，其下层 `93E0A0` 保存窗口模式标志。模式1为普通窗口路径。
- 模式0随后在 `A5A76E` 调用 `943260(1,0)`；`9433D4` 将窗口样式设为2，`9433E7..9433F7` 使用显示区域尺寸，`943470..943499` 设置位置与大小。`93E29B..93E2D1` 根据样式索引查表；`C704B0[2]=0x80080000`，`C704E0[2]=0`，无标题栏/边框位。这是窗口模式下自定义的无边框全屏。其他标志（含-1）涉及额外启动分支，本模块不替用户猜测。
- `93E3E2..93E40D` 的普通比例计算使用 `CVTTSD2SI` 截断为整数，但其前后还有DPI、菜单和窗口边框计算。宿主 `initial_client_size` 暂采用正数截断并最少1像素；完整原生像素舍入未宣称闭合。

以上新地址可用当前EXE的有界反汇编复核，例如 `objdump -D -M intel --start-address=0x943260 --stop-address=0x9434d0 GamePro.exe`、`0x768720..0x7687C0`、`0x93E120..0x93E9A0`。IAT名字通过PE导入目录解码，常量表通过对应RVA直接读取。

## 缺文件与宿主资源上限

INI读取函数 `9B8B30` 在打开返回0时走 `9B8D4B..9B8D7B`，随后 `9B8D87..9B8DA5` 构造空文本并继续键默认值解析。零字节文件也汇入空文本路径。因此Game.ini缺失不应阻止启动：`read_ini` 仅对NotFound返回空文本，其余I/O故障保留明确诊断；输入最多1MiB。此限制以及对其他I/O故障的诊断属于宿主策略。原生输入构造在 `9B8D34` 使用strlen，模块因此在NUL处截断，缩放值不跨行吞入后续数字。没有证明Game.dat缺失时可以正常启动，不能将Game.ini的默认策略推广到归档配置。

宿主逻辑分辨率单边限制8192，单张RGBA像素缓冲限制64MiB，乘法使用checked算术。这是资源限制而非原生格式宣称；超限报错而不悄悄换成1280×720。`allocate_rgba` 使用 `try_reserve_exact` 报告分配失败。`initial_client_size` 独立验证最终物理窗口尺寸与有效比例，避免极小倍率产生0尺寸、无可用显示器时极大倍率直接转换成巨型窗口。平台层仍须检查设备实际 `max_texture_dimension_2d`，再创建纹理或配置surface。

9项测试通过，覆盖不同逻辑分辨率、原生默认和正倍率、总RGBA与单边上限、超大/非数值缩放、最小物理尺寸、显示器编号与固定取值字符数、重复键/NUL/行边界、缺失Game.ini。没有用运行游戏或修改原游戏配置来完成这些检查。

## 当前平台接入

main和Game服务都通过有上限的 `read_ini` 读取配置，启动图像使用 `allocate_rgba`，窗口尺寸通过 `initial_client_size` 校验。0号显示器根据鼠标位置计算最近显示器；正数使用减1后的明确索引，越界时宿主报错（原生函数返回-1且保留已有选择，这一处是诊断策略差异）。普通窗口按选中显示器与实际外框大小居中。

WindowModeFlag=0映射到winit的Borderless(selected monitor)，1保留普通窗口。它复现显示器大小的无边框呈现，未逐字节重现原生943260的临时绘图面和窗口样式转换。其他未恢复标志明确报错。Display在首次创建纹理和配置surface前检查实际设备 `max_texture_dimension_2d`；原有resize路径继续使用设备上限。
