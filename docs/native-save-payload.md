# 原生存档快照结构校验

2026-11-17。`native_save_payload.rs` 接收外层已解密、解压并完成身份校验的快照字节，从版本字段之后开始，包含最后的 `0x19`。当前仅接受版本158；其他版本明确返回unsupported。解析成功意味着此版本的结构遍历、结束标记和精确EOF均通过，不代表恢复运行中的地图、图片或脚本实例。

读取顺序来自 `9AF230` 的查询分支；REA导出保存在 `docs-append/evidence/startup-native`，主要批次Evidence为 `ev_2ed7d9391b66954bd85b0bb5f536b97b10d17aa01efe947c31f0573dd77fbf0a`。读取函数依次为94BB60、9FBB00、95C020、9E6240、9F5EB0、9A6710、948A10、943DF0。9A6390在前置路径只重置状态，不消耗快照。

## 完整遍历的边界

- 94BB60：数值键及字符串键的二维整数数组，各层分别使用i32或u16计数。
- 9FBB00：地图、尺寸、图层、tile或−1标志、32段字符串、整数向量、地图角色和附加名称，以及版本附加字段。tile分支的第一个i32是窥读；普通数据分支不能多消耗4字节。
- 9EE140：地图和队伍共用的角色记录，包含两次56ECE0移动记录。56ECE0不是容器resize：每次读取6个字节、i32指令数，再读取56E580记录的opcode、参数数和原始字节字符串。漏掉这两次调用会使下一个角色字符串错位。
- 95C020：系统字段、字符串和若干映射。保留原生对象目的偏移，以免将文件位置和对象偏移混淆。最后96053A处的count决定是否读取一个i32，并非读取count个i32。
- 9E6240：事件自身数组、数值库、字符串、公共自身数值和字符串，以及版本149之后的键/字节映射。
- 9F5EB0：首角色、附加角色、两个标志及整数/整数对向量。
- 9A6710：i16图片数，逐项981750读取后再调用一次97EED0读取附加图片表。当前真实fixture的图片数为0；非零图片结构按981750的版本158分支遍历，尚无真实非零图片存档验收。
- 948A10：头字节、类型数与6C4130类型记录。保存模式跳过外部dat的metadata字符串；5716A0按1000/2000字段编码读取数值/字符串行。6C4130的局部反汇编保存在 `validation/native-save/6C4130-alignment.asm`。
- 943DF0：启用标志为1时读取带tag的列表；tag小于250使用单字节值，否则使用i32。随后必须立即遇到0x19和文件结尾。

普通字符串要求声明范围内存在末尾NUL，保留原始字节而不猜编码。56E580的单字节长度字符串使用不同布局：允许长度0，不要求序列化NUL。不能因一次错位就放松所有字符串的终止校验。

## 有效标志与保留字段

9000024 getter读取系统对象偏移2356；该字段不是95C020序列化内容。仅在所有快照段、trailer和EOF通过后，宿主才能发布有效状态。`SaveSnapshot`保留系统字段、原生变量分组、公共变量、可变数据库行和段范围，用于后续查询；未证明的selector不能仅按容器顺序猜测。当前部分字段尚未被查询服务消费，代码中的局部dead_code说明标明了保留原因。

限制为64MiB payload、单个和累计计数预算100万。乘法和游标加法检查溢出，负数、截断、超预算和多余尾部字节都失败。这些资源上限属于宿主策略，并非原生格式最大值。
