# 确定性回放

`wolf_vm::replay` 实现实施计划 §6.3–6.4 的 tick 输入日志与状态哈希验证。它验证当前 Rust 运行时规则的可重复性，不证明与原版行为一致。

初始化变量、创建事件后，将 `Vm` 交给 `Recorder::new(vm, max_frames)`。每次 `tick(Input)` 按顺序写入 globals、systems，再提交服务 completions 并执行一个逻辑 tick。重复变量写入保留顺序。记录器仅提供不可变 VM 引用，避免绕过日志修改状态。

```rust,ignore
let mut recorder = Recorder::new(vm, 3600)?;
recorder.tick(Input::default())?;
let (_, tape) = recorder.finish();
let bytes = tape.to_bytes(16 << 20)?;
let tape = Tape::from_bytes(&bytes, 16 << 20, 3600)?;
let replayed = tape.verify(library, new_session, 16 << 20)?;
```

当前日志版本为 v3（`replay::VERSION`），嵌入的 VM 存档另有版本，当前为 v11；旧日志不会猜测迁移。日志包含初始新格式存档、初始状态哈希、逐 tick 输入和执行后的状态哈希。验证先恢复并核对初始状态，即使没有任何帧也能发现初始存档的意外变化；随后要求连续 tick，并在首次状态分歧报告 tick 与预期/实际哈希。哈希是运行一致性检查，不是签名或防伪认证：同时改写输入与对应哈希仍可构造另一份有效日志。当前验收范围见 [续作记录](runtime-status-20261118.md)，通用回放不等于全部播放器原生服务的端到端回放。

恢复时只重绑定原有效会话的完成 token，过期 token 保持过期；新会话必须大于初始会话，且不能与日志中任何过期代次冲突，包括数值大于初始会话的代次。重复 token 仍按 VM 策略整组拒绝。程序库由调用者提供，存档恢复检查其身份；逻辑状态哈希排除运输会话代次，保留请求序号。

`Tape::from_bytes` 先检查调用者的总字节上限，再用带上限的序列访客读取初始存档与帧数组。超过帧数时在解析额外帧前拒绝，输入三个数组也在读取期间受限制；不根据 JSON 的长度提示预分配。拒绝缺失、重复、未知字段、尾随数据和非 64 位小写十六进制哈希。初始存档的执行状态有效性由 `Vm::restore` 检查。

| 对象 | 硬上限与调用者限制 |
|---|---|
| JSON 输入/输出 | `min(cap, 512 MiB)`，输出在写入过程中检查 |
| 初始存档 | 256 MiB；验证时另受 `save_cap` 限制 |
| 帧数组 | `min(max_frames, 1,000,000)` |
| 单帧 globals / systems / completions | 每个数组最多 1,000,000 条 |
| `Failed` 文本 | 16 MiB UTF-8 字节；VM 自己还应用其完成响应长度策略 |

这些是收集到的元素与编码字节上限，不是进程内存预算：JSON 解码临时缓冲、向量容量、状态快照与调用者已经创建的 `Input` 也占内存。应使用 `from_bytes` 作为不受信任日志入口；直接调用通用 `Deserialize` 没有调用者指定的总字节限制。

记录器在写入前预检两个变量空间的索引、全部新增槽位（重复键只计一次）、完成批量大小与 tick 溢出；任一失败时 VM 和成功日志前缀都不变，可继续提交合法输入。帧数耗尽同样在变更前拒绝。有效 VM 的保留队列与 ID 不变量保证其余 tick 级检查通过；指令执行故障是帧内诊断，仍作为成功 tick 记录。记录器保留针对内部 tick/hash 错误的停止锁；若触发该内部错误，应丢弃返回 VM，使用成功日志前缀恢复。

当前日志覆盖变量输入和服务完成，不提供运行途中 spawn、取消、页面替换的日志操作，也不记录图像或音频输出。回归测试覆盖跨会话回放、旧/未来过期 token、重复 token、连续 tick、编码/解码边界、损坏存档、初始哈希、输入分歧定位与无副作用的失败输入。
